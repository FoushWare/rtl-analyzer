# Project-wide review navigation

This record supersedes the file-scoped navigation/summary behavior described in the earlier dashboard verification records; those records remain historical evidence for their packages.

## Cause and scoped fix

The approval dialog, persistent Decision-side action and summary used `rtlDashboardVisibleFindings()`, whose result includes Explorer's selected-file filter. The top navigation independently used that same file-local list. Consequently the last main.tsx finding offered a file-only summary while reading.css still had Pending findings.

`dashboard-review-navigation.ts` now provides one pure progress model used by the dialog, Decision-side action, top/legacy navigation, counter and summary. It separates:

- review scope: all reviewable findings in the selected workspace/project and existing workflow scope;
- presentation filters: search, severity, category, eligibility and sort;
- current-file ordering: used for Previous/Next and explicitly labeled **In file** counters;
- persisted decisions: Pending drives continuation; Deferred and Flagged/Needs review remain unresolved; Rejected is reported separately.

At a file boundary, remaining Pending work in other files yields **Continue to next file**, with destination source path and both destination/project Pending counts. Continuation is explicit; approval still persists first and opens confirmation without advancing. Selection uses the existing finding selection path, synchronizing Explorer, sidebar, URL, previews and heading focus. The existing note draft map is preserved across file selection.

Search and finding filters never reduce review scope or summary totals. Hidden work is explained before an explicit continuation clears those filters, keeping workspace/project scope. A no-results filter gets an explicit recovery action as well. Filters are not silently discarded. When only Deferred/Needs review work remains, guidance offers the summary rather than cycling; **Review unresolved** lists individual destinations for explicit return. The sole Pending current finding cannot navigate to itself. A summary with unresolved findings does not claim completion.

The summary reports accepted, rejected, unresolved and Pending counts across the whole selected scope, explains that validation/Apply remain separate, and offers validation under existing accepted-subset rules. No backend eligibility, transformation, identity, direction, source hash, validation, Apply or rollback safeguard was weakened. No target CSS, fixture source or project was added or changed.

Browser verification exposed a filter refresh path that updated the list without rebuilding the selected detail. That path now refreshes navigation from the same model. Browser scroll anchoring caused a two-pixel page shift while the review pane rebuilt; disabling anchoring on that pane preserved the existing strict scroll assertion and preview height reservation. Destination details sit below Decision buttons so they do not squeeze controls. Decision `aria-pressed` is applied only to decision buttons, excluding navigation and explanatory text.
