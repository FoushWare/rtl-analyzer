## Causes and changes

- **Last CSS finding:** `.unmapped{padding-left:6px}` is intentionally omitted from the Field Notes preview configuration. Its DOM explicitly says “Deliberately unmapped.” This negative case remains unmapped. Successful context responses with no route now show the requested compact accessible “Live preview unavailable” state and exact explanatory message, with unavailable preview controls hidden. Source, proposed code and Decision navigation remain available. Context/runtime failures retain their separate error and recovery controls.
- **Name and email:** the fixture configuration previously contained CSS mappings only. Adding the two TSX bindings also exposed a resolver restriction: `sourceSelector` matched CSS contexts only. The generic resolver now recognizes simple literal class/id selectors in TSX, associates the actual JSX expression text and exact source offsets with the configured element, and leaves runtime target verification mandatory. It does not claim a JSX selector is a loaded CSS rule. Candidate bindings use the original source anchors because inserting `<bdi>` changes candidate offsets; candidate runtime/source hashes still identify actual candidate files. Fixture-specific `.contact-name`/`.contact-email` bindings remain solely in the disposable fixture configuration, using existing external configuration fields.

Accepted ✓, Rejected ×, Deferred ◷, Pending ○ and Flagged/“Needs review” ◇ have labels/tooltips and distinct colors. No Skipped state or duplicate decision store was added. Selected styling is separate. Rerendered rows are refreshed from the same workflow; historical/noncurrent workflows render Pending.

The existing dashboard, transformation inventory, source identity, approval eligibility and validation/Apply safeguards are preserved. Supported transformation and verified visual preview remain separate.
